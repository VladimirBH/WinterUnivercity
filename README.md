# Сквозь века — WinterUnivercity

Исторический путеводитель по Великому Новгороду. В демо комплекс «Церкви на Бредова-Звериной» объединяет место Лазаревской церкви и сохранившуюся церковь Петра и Павла в Кожевниках. У каждой церкви своя точка на карте, карточка, исторические виды и источники. Комплекс объединяет соседние точки для прогулки в приложении.

| Папка | Содержимое |
| --- | --- |
| [`backend/`](backend/) | FastAPI, готовая база SQLite, локальный каталог для Android и изображения. |
| [`frontend/`](frontend/) | Android-приложение на Jetpack Compose. |
| [`3dModeling/`](3dModeling/) | Сцены Blender, превью, модели и исторические материалы. |

## Запуск

Для сервера нужен Python 3.11 или новее. В PowerShell из корня проекта выполните:

```powershell
python -m venv backend/.venv
& .\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
& .\backend\.venv\Scripts\python.exe backend/main.py
```

В Linux или macOS создайте окружение через `python3 -m venv backend/.venv` и используйте `backend/.venv/bin/python` для команд установки и запуска.

Сервер по умолчанию слушает `127.0.0.1:8080`. Откройте [Swagger UI](http://127.0.0.1:8080/docs) или [JSON карты](http://127.0.0.1:8080/api/v1/map). Адрес и порт задаются через `HOST` и `PORT`. Путь к другой копии базы той же версии можно указать через `SKVOZ_DB_PATH`. Относительный путь в этой переменной считается от рабочего каталога процесса. При запуске сервер проверяет доступность SQLite и версию схемы.

Для Android откройте `frontend/` в Android Studio, выберите JDK 21 для Gradle и запустите модуль `app` на эмуляторе. Debug-сборка обращается к серверу через `10.0.2.2:8080`. Сервер также можно запустить задачей Gradle `runBackend`, передав путь к Python из окружения через `-PpythonExecutable`.

## Backend

[`backend/main.py`](backend/main.py) содержит маршруты FastAPI, подключение SQLite к запросам и выдачу медиа. [`backend/store.py`](backend/store.py) выполняет запросы к базе и формирует ответы. [`backend/schemas.py`](backend/schemas.py) описывает ответы для OpenAPI.

API публичный и доступен на чтение. Для каждого запроса открывается соединение SQLite в режиме `mode=ro` с включённой проверкой внешних ключей. Сервер читает одну согласованную версию данных в рамках запроса.

| GET | Ответ |
| --- | --- |
| `/api/v1/map` | Общая схема, точки памятников и маршрут по умолчанию. |
| `/api/v1/complexes` | Список комплексов с количеством памятников. |
| `/api/v1/complexes/{slug}` | Карточка комплекса, его памятники, общие источники и ссылки на маршруты. |
| `/api/v1/complexes/{slug}/map` | Точки и маршрут выбранного комплекса на его схеме. |
| `/api/v1/monuments/{slug}` | Карточка памятника, ссылка на комплекс, даты и перечень построек. |
| `/api/v1/monuments/{slug}/comparison` | Упорядоченные исторические виды с изображениями, ссылками на модели и связанными источниками. |
| `/api/v1/monuments/{slug}/source` | Первый по порядку источник для текущего Android-экрана. |
| `/api/v1/monuments/{slug}/sources` | Все источники отдельного памятника. |
| `/api/v1/monuments/{slug}/ar` | Инструкция, метка при наличии, модели и ссылка на сравнение без камеры. |
| `/api/v1/routes/{slug}` | Точки линии и остановки. Остановка может ссылаться на карточку памятника. |
| `/media/{path}` | Изображение, PDF или 3D-модель, зарегистрированные в каталоге. Сохранены прежние URL четырёх JPEG-файлов. |

Примеры идентификаторов в демо:

- Комплекс — `tserkvi-na-bredova-zverinoy`.
- Памятники — `tserkov-lazarya` и `tserkov-petra-i-pavla-v-kozhevnikah`.
- Маршрут — `dve-tserkvi`.

Существующие Android-экраны продолжают использовать прежние URL. Даты в карточке могут быть `null`, например год утраты сохранившегося храма. Android отображает только доступные даты. При сетевой ошибке debug-сборка пробует встроенный [`catalog.json`](backend/catalog.json), а релизная сборка читает его напрямую. Офлайн-каталог охватывает первоначальный сценарий с церковью Лазаря. Для комплексов и маршрутов сервер предоставляет API. В Android точки открывают карточки отдельных памятников, медиа остаются серыми полотнами, а камера и переключение эпох демонстрируют сценарий вручную.

Флаг `arAvailable` становится `true`, когда доступны файл цели распознавания и хотя бы одна модель памятника. В демо есть две модели `.glb`, а цель распознавания пока не задана. Сравнение без камеры доступно для обеих церквей. Маршрут демонстрационный, координаты точек на схеме указаны в диапазоне от 0 до 1 от её левого верхнего угла.

## База данных

[`backend/skvoz-veka.sqlite3`](backend/skvoz-veka.sqlite3) — источник данных API. Версия схемы записана в `PRAGMA user_version` и равна `1`. В демо один комплекс, два памятника, три исторические постройки, пять видов, шесть исторических источников и один маршрут с тремя остановками.

| Таблица | Назначение и связи |
| --- | --- |
| `complexes` | Карточка комплекса, его основная схема `map_id` и обложка. |
| `monuments` | Карточки церквей и других объектов. Один памятник может входить в один комплекс через `complex_id` или быть самостоятельным. |
| `monument_buildings` | Постройки на месте памятника. `built_year_end` задаёт конец диапазона постройки, например 1861–1862. Даты в верхней части карточки берутся из первой постройки по `sort_order`. |
| `monument_views` | Современный и исторические виды памятника, возможная ссылка на его постройку, изображение и 3D-модель. Идентификатор вида уникален в пределах памятника. |
| `maps` | Схемы с городом и системой координат. Общий `/map` использует первую схему по `id`. |
| `map_markers` | Координаты памятника на конкретной схеме. |
| `routes` | Маршруты на схеме, при необходимости привязанные к комплексу. Маршрут по умолчанию выбирается по `sort_order`, затем по `id`. |
| `route_points` | Точки линии маршрута в порядке `position`. |
| `route_stops` | Подписанные остановки на точках линии. Внешний ключ связывает пару `(route_id, point_position)` с точкой маршрута. |
| `historical_sources` | Общие записи о материалах с авторством, коллекцией, страницей локального PDF или внешней ссылкой. |
| `complex_sources` | Связь источника с комплексом, пояснение и порядок показа. |
| `monument_sources` | Связь источника с памятником, пояснение и порядок показа. |
| `view_sources` | Связь источника с конкретным историческим видом и пояснение о реконструкции. |
| `ar_configs` | Инструкция, превью стенда и файл цели распознавания для памятника. |
| `media_assets` | MIME-тип и путь к файлу от корня проекта. Двоичные файлы хранятся в `backend/media/` или `3dModeling/`. |

Церковь Лазаря представлена одной карточкой и двумя постройками, каменным храмом 1461 года и храмом 1861–1862 годов. Для ранней реконструкции есть превью и отдельный экспорт OBJ. В API к поздней реконструкции привязан `Lazarus_1862_AR.glb`. К виду церкви Петра и Павла в XIX веке привязан `Peter_Paul_Kozhevniki_XIX_v8.glb`.

При переносе проекта сохраните файл SQLite и медиа по путям из `media_assets`, включая три PNG/JPEG-превью и исторический PDF из `3dModeling/`. Схему можно просмотреть командой `sqlite3 backend/skvoz-veka.sqlite3 .schema` или в SQLite-редакторе. При редактировании данных включите внешние ключи и после изменений проверьте `PRAGMA integrity_check` и `PRAGMA foreign_key_check`. При изменении структуры базы обновите `user_version`, запросы и модели ответа вместе.
